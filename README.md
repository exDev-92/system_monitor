# Мониторинг ПК

Панель аппаратного мониторинга для второго монитора (Full HD, тёмный матовый интерфейс).
Electron + React + Vite, данные собирает Python-бэкенд (`backend/monitor.py`).

## Три варианта дизайна

Реализованы все три направления из дизайн-хендофа, каждое в двух раскладках —
**полный экран 1920×1040** и **половина экрана 960×1040** (40 px под панель задач Windows уже вычтены):

| Вариант | Название | Характер |
|---|---|---|
| `1a` | Плотный пульт | кольцевые датчики, много мелких цифр, моноширинный шрифт |
| `1b` | Сетка карточек | спокойнее, воздуха больше, крупные значения |
| `1c` | Индустриальный HUD | круглые датчики и шкалы, узкая гарнитура |

Переключение:

- **клавиши `1` / `2` / `3`** — вариант дизайна;
- **`F3`** — окно статистики;
- **`F2`** — окно настроек (вариант, режим окна, автозапуск, трей, период опроса, журнал, состояние датчиков);
- плавающие кнопки в правом верхнем углу — появляются при наведении мыши на окно;
- **значок в трее** — клик показывает и прячет окно, правый клик открывает меню.

### Режимы окна

| Режим | Размер на Full HD | Панель задач |
|---|---|---|
| Как есть | не меняется | — |
| Весь экран | 1920×1040 | видна |
| Половина экрана | 960×1040, справа | видна |
| Полноэкранный | 1920×1080 | перекрыта, окно поверх всех |

Выбор режима сразу задаёт размер окна; «Как есть» окно не трогает и подбирает макет
по его ширине. Выбор сохраняется в `localStorage`.

Масштабирование считается **по высоте**: базовая высота макета 1040 px, ширина кадра
подстраивается под окно. Поэтому чёрных полей нет ни при каком размере, вертикальная
геометрия дизайна (кольца 262 px, нижняя полоса 214 px) сохраняется точно, а на мониторах
крупнее Full HD всё пропорционально увеличивается вместо того, чтобы «поплыть».

Цвет в интерфейсе появляется только при отклонении от нормы: нейтральный серый → янтарный
(«тепло») → красный («жарко»). Пороги заданы в [src/designs/tokens.ts](src/designs/tokens.ts).
Отсутствующий датчик показывается прочерком, а не нулём.

### Трей

Значок в трее держит приложение запущенным, когда окно не нужно. Меню значка
повторяет главное: показать или скрыть окно, вариант дизайна, «поверх всех окон»,
настройки и выход.

Галка **«Крестик сворачивает в трей»** (включена по умолчанию) решает, что делает
закрытие окна: спрятать его в трей или выйти совсем. Выход доступен из меню значка
в любом случае, так что запереть себя в трее нельзя.

Пока окно скрыто, метрики в него не отправляются вовсе — работает только бэкенд
и подсказка значка с текущими температурами. Это снимает сериализацию IPC и
перерисовку интерфейса, то есть почти всю цену работы приложения.

Второй запуск не поднимает второе приложение: он показывает окно уже работающего.

### Автозапуск

Галка «Запускать при входе в Windows» создаёт задачу планировщика `PCMonitor Autostart`:
приложение стартует скрытым, в трее, с правами администратора и без окна подтверждения.
Менять галку можно только при запуске от администратора.

Упавший или зависший бэкенд перезапускается сам, а окно показывает, что данные устарели.

### Журнал

Пишется всё время работы приложения, в том числе при заблокированном экране и в трее.
Папка `%APPDATA%\PCMonitor\logs`:

| Что | Содержимое |
|---|---|
| `short/` | CSV, каждый опрос, хранятся последние минуты (по умолчанию 60) |
| `long/` | CSV, минимум, среднее и максимум за период, хранится долго, старое сжимается gzip |
| `events.log` | запуск и выход, сон, блокировка, перегрев, перезапуски бэкенда |
| `incidents/` | копия записей перед сбоем, в автоочистку не попадает |

Разделитель `;`, по умолчанию десятичная запятая для русского Excel (в pandas:
`read_csv(path, sep=';', decimal=',')`). Срок хранения, лимит папки, состав данных
и интервал сброса на диск меняются в настройках.

### Статистика

Окно открывается по `F3`, из меню значка и кнопкой на панели. Показывает журнал за выбранный
период: максимумы и итоги сверху, графики температур, загрузки, мощности, сети и дисков, список
событий. Наведение мыши показывает точки и время сразу на всех графиках, выделение приближает.

Голубая зона в конце графиков — данные короткого журнала, с реальной частотой записи; левее
средние значения из долгого журнала. Серые участки подписаны: сон, выключен, сбой.
При закрытии окно выгружается и памяти в фоне не занимает.

### Настройки

Хранятся в `%APPDATA%\PCMonitor\config.json` и принадлежат главному процессу —
их читают и меню трея, и интерфейс. Файл можно править руками: каждое поле
проверяется по отдельности, мусор в одном ключе не ломает остальные настройки.

```

  designs/

    snapshot.ts        Metrics → Snapshot + кольцевые буферы графиков (90 значений)
    primitives.tsx     Ring, Spark, Bar, ThreadBars, FanDial
    DenseConsole.tsx   1a  (dense.css)
    CardGrid.tsx       1b  (cards.css)
    IndustrialHud.tsx  1c  (hud.css)

electron/config.ts     config.json: схема, проверка значений, атомарная запись
electron/autostart.ts  автозапуск через планировщик заданий
electron/journal.ts    журнал показаний и событий
electron/stats.ts      чтение журнала для окна статистики
src/stats/             окно статистики (тот же бандл, index.html#stats)
src/settings/          окно настроек (тот же бандл, index.html#settings)

```

## Датчики

Загрузка ЦП по потокам, память, подкачка, диски и сеть идут через `psutil`,
видеокарта — через `pynvml` (NVML).

Всё, что читается на уровне ядра — температуры ЦП по ядрам, реальные частоты,
обороты и PWM вентиляторов, hotspot видеокарты, температуры и SMART накопителей,
температуры плашек памяти — берётся из **LibreHardwareMonitorLib, встроенной в
приложение** ([backend/lhm.py](backend/lhm.py)). Отдельное приложение запускать не нужно:
библиотека приходит с pip-пакетом `HardwareMonitor` и работает через драйвер **PawnIO**.

PawnIO выбран вместо WinRing0 намеренно: WinRing0 даёт произвольный ring0-доступ
любому процессу и находится в блок-листе уязвимых драйверов Microsoft, а PawnIO
подписан и исполняет только ограниченные Pawn-модули в песочнице.

Если PawnIO или пакет недоступны, приложение автоматически откатывается на WMI
внешнего LibreHardwareMonitor, а затем на ACPI/psutil.

### Установка PawnIO

Без PawnIO приложение работает, но показывает только загрузку, память, диски и сеть.
Установщик проверяет, есть ли драйвер, и предлагает поставить его. То же умеет кнопка
в настройках (`F2` → «Датчики»).

Установщик PawnIO в наш пакет не входит: права на его распространение не подтверждены.
[build/pawnio-install.ps1](build/pawnio-install.ps1) скачивает его со страницы автора
(`github.com/namazso/PawnIO.Setup`), проверяет, что цифровая подпись действительна и
выдана именно автору, и только тогда запускает. Вручную — [pawnio.eu](https://pawnio.eu).

### Жёсткие диски

Чтение SMART выполняет сам диск, поэтому опрос раз в секунду не даёт HDD уснуть,
а у дисков с агрессивной парковкой головок (например, WD Green) вызывает щелчки и износ.
По умолчанию приложение не обращается к жёсткому диску, пока он простаивает:

- температура и SMART читаются, только когда к диску и так обращаются другие программы,
  и не чаще раза в 5 минут;
- остановленный диск не будится никогда — состояние проверяется через
  `GetDevicePowerState`, на панели вместо температуры «сон»;
- свободное место запрашивается заново только после записи на диск или раз в полчаса.

Режим меняется в настройках: «Каждый опрос» — как раньше, «Не читать» — совсем без SMART.
Тип диска берётся из Storage Management API Windows; если тип не указан (так бывает у
WD Green), диск считается жёстким, кроме NVMe. SSD опрашиваются на каждом опросе.
В `events.log` видно, когда жёсткий диск останавливался и раскручивался.

### Другое железо

Имена датчиков зависят от вендора, поэтому поиск ведётся по списку вариантов:
температура ЦП — `CPU Package` (Intel) или `Core (Tctl/Tdie)` (AMD Zen), максимум по
ядрам — `Core Max` или `CCDs Max (Tdie)`, мощность — `CPU Package` или `Package`.

Видеокарта читается через NVML (NVIDIA), а если его нет — через LHM, что покрывает
Radeon и Intel Arc: загрузка, температура, hot spot, VRAM, частоты, вентилятор.

Накопители сопоставляются с буквами томов по модели, с запасными вариантами по
вхождению строки и по номеру физического диска. Вентиляторы получают осмысленные
подписи там, где плата их отдаёт (`CPU Fan` → «ЦП», `Chassis Fan 2` → «КОРПУС 2»),
иначе нумеруются как «ВЕНТ N».

Проверено на Intel Core i7-13700KF + RTX 4070 Ti. AMD-конфигурация не тестировалась —
имена датчиков взяты из исходников LibreHardwareMonitor.

### Права администратора

PawnIO отдаёт данные только процессу с правами администратора. Собранное приложение
запрашивает их само (`requestedExecutionLevel: requireAdministrator`). В режиме
разработки `npm run dev` прав нет — температуры и вентиляторы будут прочерками,
а в шапке появится «НЕТ ПРАВ АДМИНИСТРАТОРА». Панель настроек (`F2`) показывает
состояние источника и кнопку «Перезапустить от администратора».

## Запуск

```bash
npm install

pip install psutil pynvml wmi HardwareMonitor pyinstaller
# драйвер датчиков — https://pawnio.eu, или build\pawnio-install.ps1

npm run dev      # разработка (без прав администратора)
npm run build    # сборка дистрибутива
```

`HardwareMonitor` требует .NET Framework 4.7+ — на Windows 10/11 он уже есть.

`npm run build` нужно запускать **из консоли администратора**: иначе electron-builder
не распакует `winCodeSign` — 7-Zip не может создать символические ссылки без прав.

## Дистрибутив

Бэкенд собирается PyInstaller-ом в самостоятельный exe (`npm run build:backend`,
~34 МБ) и кладётся в `resources/backend/sysmon-backend/`. **На целевой машине Python
не нужен** — приложение запускает exe, а на исходники `monitor.py` откатывается только
в разработке. Из внешнего остаётся один PawnIO — его предлагает поставить установщик.

Установщик: `release/<version>/PCMonitor-Windows-<version>-Setup.exe` (~95 МБ).
Приложение запрашивает права администратора при запуске. Готовый установщик
выкладывается в GitHub Releases, в сам репозиторий сборки не попадают.
